# Этап 2 — серверное ядро и базовый API

## Реализовано в этой ветке

- PDO-подключение к MySQL с отключённой эмуляцией prepared statements.
- Внешний конфигурационный файл, путь к которому передаётся через `SVET_CONFIG_FILE`.
- Минимальный роутер и JSON-формат ответов.
- API: health, проверка БД, филиалы, категории, список товаров, карточка товара.
- Гостевая регистрация устройства по UUID.
- Bearer-токены: в БД сохраняется только SHA-256-хэш токена.
- Получение текущего пользователя и отзыв токена.
- Публичная точка входа и Apache rewrite.

## Пока не реализовано

- Миграционный runner и применение SQL к тестовой MySQL.
- OAuth VK ID / OK / Yandex ID.
- Импорт XLSX и журнал ошибок.
- История цен, подписки и OneSignal.
- Админ-панель, CSRF и управление ролями.
- Полный набор интеграционных и API-тестов.

## Настройка для локальной/тестовой среды

1. Установить зависимости командой `composer install`.
2. Скопировать `backend/config/config.example.php` в файл вне публичного каталога.
3. Заполнить доступы к тестовой MySQL и экспортировать абсолютный путь в `SVET_CONFIG_FILE`.
4. Применить миграцию из `database/migrations` после отдельной проверки на тестовой БД.
5. Настроить document root на `backend/public`.
6. Проверить `GET /api/v1/health`, затем `GET /api/v1/health/db`.

Не размещайте `backend/`, `vendor/`, миграции, конфигурацию и логи в публичном web-каталоге. На рабочем сервере пока ничего не запускать.
