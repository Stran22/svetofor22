# Светофор Android — технический стек и проверка Push

Дата актуализации: 2026-11-10. Серверная документация: [Stran22/svet — стек и сквозной тест](https://github.com/Stran22/svet/blob/main/docs/TECHNICAL_STACK_AND_PUSH_2026-11-10.md).

## Назначение
Нативное Android-приложение каталога товаров двух филиалов без корзины и оплаты. Показывает цены и наличие; пользователь может отслеживать отсутствующий товар и получать уведомление о поступлении.

## Подтверждённые технологии
- Kotlin, Jetpack Compose, Material 3.
- Firebase Cloud Messaging (FCM).
- REST API PHP/MySQL сервера `baza.altaj-otdyh.ru`.
- Разработка/сборка через Android Studio Panda 4; ранее успешно использовались `minSdk 24`, `targetSdk 34`, `compileSdk 34`, но **текущие значения и зависимости следует проверять в Gradle-файлах конкретной ветки**. В новом ТЗ также фигурировал минимум API 26; без сверки файлов нельзя объявлять ни одно значение текущим.

## Подсистема подписок
- `FcmRegistrationManager.kt`: постоянный идентификатор устройства, регистрация FCM-токена на сервере, хранение API bearer.
- `SubscriptionRepository.kt`: API-операции с подписками.
- `ProductDetailScreen.kt`: действие отслеживания товара.
- `TrackedScreen.kt`: отображение отслеживаемых товаров.
- Гостевая подписка использует авторизацию устройства по API bearer; для неё не требуется отдельная социальная авторизация.

Указанные имена файлов и поведение основаны на выполненной ранее работе и проверках. Эта запись **не заменяет аудит текущего содержимого ветки**.

## Подтверждённый сквозной тест — 2026-11-09
1. Товар `product_id=3` («Хлеб белый, 400 гр»), филиал `branch_id=1` («На Волочаевской»), активная подписка `subscription_id=3`.
2. Остаток был `0`; в админ-панели изменён на `5`.
3. Сервер автоматически создал `push_delivery_log.id=4` со статусом `pending` в `21:38:59`.
4. В `21:40:01` запись получила `sent`, `attempt_count=1`, `last_error=NULL`.
5. Пользователь подтвердил: **уведомление поступило на реальный телефон, когда приложение «Светофор» было закрыто**.

Таким образом, получение FCM при закрытом приложении подтверждено на тестовом устройстве. Это не означает гарантию доставки после «Принудительно остановить», при отключённых уведомлениях, без интернета или на любых Android-устройствах. Для Android 13+ требуется разрешение на уведомления.

## Серверная обработка
PHP-обработчик `bin/process_push_queue.php --send --limit=20` работает по расписанию ISPmanager `*/5 * * * *`; FCM HTTP v1. Серверная проверка вручную дала `Processed=0; sent=0; failed=0`, `EXIT CODE: 0` при пустой очереди. Параметры хостинга, SQL и диагностика подробно описаны в серверном репозитории. Секреты и токены в документацию не включать.
