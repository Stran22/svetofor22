# VK ID — серверная настройка

Код серверной авторизации находится в `backend/app/Controllers/VkAuthController.php` и `backend/app/Services/VkIdService.php`.

## Перед развёртыванием

1. Проверьте, что в PHP 8.5 включено расширение `curl` и разрешены исходящие HTTPS-запросы к `id.vk.ru`.
2. Добавьте в **внешний** конфигурационный файл, заданный `SVET_CONFIG_FILE`, отдельный раздел массива:

```php
'vk_id' => [
    'client_id' => '54888262',
    'redirect_uri' => 'vk54888262://vk.ru/blank.html',
],
```

Уточните фактический `redirect_uri` в настройках VK ID для Android: он должен совпадать с тем, который использует SDK. Не добавляйте секрет приложения в GitHub.

3. Проверьте схему существующей таблицы `social_accounts`: контроллер ожидает колонки `user_id`, `provider`, `provider_user_id` и уникальность пары (`provider`, `provider_user_id`). Если таблица использует другие названия, сначала адаптируйте запросы контроллера. **Не создавайте таблицу повторно и не изменяйте рабочую БД вслепую.**
4. Выполните `php -l` для новых файлов и проверьте маршрут `POST /api/v1/auth/vk` на тестовой среде.

## Протокол

Android отправляет Bearer-токен текущего пользователя, `code`, `device_id` VK, `code_verifier` и `state`. PHP обменивает код у VK ID, проверяет `state`, получает идентификатор VK пользователя через `/oauth2/user_info` и только после этого меняет `is_guest` у существующей записи `users`.

Если VK-аккаунт уже связан с другим пользователем, сервер возвращает HTTP 409, не перемещая подписки и не объединяя записи автоматически.

**Не считайте вход завершённым до теста на реальном устройстве с опубликованным сервером и согласованной схемой БД.**
